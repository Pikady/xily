## 1. 功能概述

### 1.1 设计目标
设计一个简洁高效的悬浮窗，专注于核心计时功能，在有限的空间内完美融合：
- 简洁的计时器显示
- 作品选择功能
- 探索/利用模式转换

### 1.2 当前问题分析
经过代码审查发现：
1. **重复实现**: 存在两个悬浮窗实现（`FloatWindowApp.tsx` 和 `FloatWindow.tsx`）
2. **功能冗余**: 悬浮窗包含了过多与主界面重复的功能
3. **界面臃肿**: 违背了悬浮窗简洁的设计初衷
4. **用户体验**: 过于复杂的界面影响使用效率

### 1.3 设计原则
- **简洁至上**: 只保留核心功能，去除一切冗余
- **空间优化**: 在有限空间内高效布局
- **操作便捷**: 常用操作一键完成
- **视觉一致**: 与主界面保持设计语言统一
- **响应迅速**: 保证交互的即时性和流畅性

## 2. 功能需求

### 2.1 核心功能

#### 2.1.1 计时器显示
- **大字体时间显示**: 清晰可见的倒计时
- **进度指示**: 直观的进度条显示
- **状态标识**: 清晰的状态图标和文字

#### 2.1.2 模式切换
- **双模式支持**: 探索模式（蓝色）和利用模式（橙色）
- **一键切换**: 快速在两种模式间切换
- **视觉反馈**: 模式颜色的即时变化

#### 2.1.3 作品管理
- **作品选择**: 下拉选择当前作品
- **作品信息**: 显示作品名称和颜色标识
- **快速切换**: 支持快速更换作品

#### 2.1.4 基础控制
- **开始/暂停**: 一键控制计时器状态
- **停止**: 结束当前计时
- **最小化**: 收缩到最小状态
- **关闭**: 隐藏悬浮窗

### 2.2 高级功能

#### 2.2.1 智能交互
- **拖拽定位**: 自由拖拽到任意位置
- **位置记忆**: 记住用户偏好的位置
- **自动吸附**: 边缘吸附功能（可选）

#### 2.2.2 状态同步
- **实时同步**: 与主界面状态保持同步
- **跨窗口通信**: 确保数据一致性
- **状态恢复**: 重启后恢复状态

### 3.2 交互设计

#### 3.2.1 拖拽交互
- **拖拽区域**: 整个标题栏区域
- **视觉反馈**: 拖拽时透明度和阴影变化
- **边界处理**: 允许拖拽到屏幕外边缘

#### 3.2.2 按钮交互
- **主操作按钮**: 大尺寸，易于点击
- **状态切换**: 按钮图标随状态变化
- **悬停效果**: 清晰的视觉反馈

### 3.3 视觉设计

#### 3.3.1 颜色方案
- **探索模式**: 蓝色系 (#3b82f6)
- **利用模式**: 橙色系 (#f97316)
- **背景色**: 半透明白色 (rgba(255, 255, 255, 0.95))
- **边框色**: 模式对应颜色

#### 3.3.2 字体规范
- **时间显示**: 32px, 加粗, 等宽字体
- **标题文字**: 14px, 中等粗细
- **辅助文字**: 12px, 常规

#### 3.3.3 动画效果
- **状态切换**: 200ms 过渡动画
- **拖拽反馈**: 缩放和透明度变化
- **按钮交互**: 悬停和点击效果

## 4. 技术实现

### 4.1 组件架构

```
悬浮窗组件结构
├── FloatWindowContainer    // 主容器
│   ├── FloatWindowHeader  // 标题栏（包含拖拽）
│   ├── TimerDisplay       // 计时器显示
│   ├── WorkSelector      // 作品选择器
│   ├── ModeSwitcher      // 模式切换器
│   ├── ProgressIndicator // 进度指示器
│   └── ControlButtons    // 控制按钮
└── FloatWindowMinimized  // 最小化状态
```

### 4.2 状态管理

#### 4.2.1 本地状态
```typescript
interface FloatWindowState {
  isVisible: boolean
  isMinimized: boolean
  position: { x: number; y: number }
  size: 'standard' | 'compact' | 'minimal'
}
```

#### 4.2.2 共享状态
- 与主界面共享：计时器状态、当前作品、模式
- 独立管理：悬浮窗位置、显示状态、窗口大小

### 4.3 数据流

```
用户交互 → 悬浮窗组件 → 状态更新 → API调用 → 后端处理
                    ↓
               主界面同步更新
```

### 4.4 性能优化

#### 4.4.1 渲染优化
- **React.memo**: 避免不必要的重渲染
- **useCallback**: 稳定函数引用
- **状态分离**: 本地状态与全局状态分离

#### 4.4.2 交互优化
- **事件防抖**: 拖拽事件优化
- **异步更新**: 非阻塞的状态更新
- **动画优化**: CSS transform 代替 top/left

## 9. 风险评估

### 9.1 技术风险
- **跨窗口通信**: 可能存在数据不一致
- **性能问题**: 多窗口可能影响性能
- **兼容性**: 不同系统版本可能存在差异

### 9.2 用户体验风险
- **学习成本**: 新界面可能需要适应
- **操作复杂度**: 功能精简可能影响某些用户
- **视觉一致性**: 需要确保与主界面风格统一

### 9.3 风险缓解
- **渐进式发布**: 先在小范围测试
- **用户反馈**: 及时收集用户反馈
- **快速迭代**: 根据反馈快速优化
